# Creating Macros

Macro Owners can create Macros in the ID application. All Macros are created within projects with the project being like a folder that holds the Macros. All macros are associated with either a Testsite Project or a Kerf Project. In other words, macros are project-specific.

When you log in to the ID Application, the application recognizes your user permission level and opens the corresponding User Interface \(UI\) page. Macro Owners land on the Project page, where they can view existing Projects and create new macros within those Projects.

1.  Click the **Project** tab and click a Project Name.

    The Project page opens and displays two tabs, the **Macro View** and **Design View**.

2.  Click **Macro View**.

3.  Click **Create New Macro**.

    The Create New Modal opens. Step 1, General Information, opens.

    You must complete the four steps to create your Macro. As you complete each step, you select **Next** to go to the next step.

4.  Complete the fields in the Create New Modal, Step 1.

    |Attribute|Description|
    |---------|-----------|
    |**Macro Name**|Name of the macro. Character limitation is <29 characters.|
    |**Macro Type**|Classification of the macro. The default is DC.|
    |**Owner**|Select from drop-down menu. Multiple users can own and use a Macro simultaneously.|
    |**Designer**|Optional macro designer.|
    |**Team Permission**|Grant specific teams permission to view this macro. If no teams are selected, all teams in the project can access by default.|
    |**Purpose**|The purpose is based on the project level purpose.|
    |**Priority**|Designate assigned priority on macro being placed in the project.|
    |**iftCL Name**|Designated macro centerline model name. 8‑character field: The first 5 are the project centerline prefix, followed by 3 randomly generated characters. Default value = **Autogenerated**. This macro identifier is unique for each macro.|
    |**ilt3D**|Describes where macro is testable. Select **Frontside** \(default\) for macros where only the frontside is testable. Select **Both** for macros where both the frontside and grindside are testable.|
    |**Test Lab**|Test lab where where macros are most often tested. Default to: ANT-B255-NanoTech|
    |**PadSet Model**|Padset model found in design data. Project Managers assign PadSets to Macros. Only assigned PadSets can be selected.|
    |**Description**|Optional macro description.|

    **All the above changes are applicable only for testsite project**.

5.  Click **Next** to proceed to Step 2.

    Step 2 Aspects modal opens and displays a table of Key Value Pairs for Aspects.

7.  Click **Next** to proceed to Step 3.

    Step 3 Attachment modal opens.

8.  Click **Upload** to upload supplementary materials.

    File sizes up to 500 kb are supported. File types that are supported are pdf, ppt, and doc.

9.  Click **Design View** on the Macro Creation view and select **Devices** to associate with this macro.

10. Click **Next** to proceed to Step 4.

    Step 4, the Review and Save modal opens.

11. **Review** all the configuration for your Macro. Complete your review and click **Create**.

    The system notifies you that your Macro is created and displays a timestamp of Macro creation. Your Macro is listed at the end of the Macro View list.

    **Note:**

    Each Macro is created under a specific Project and might be used only or the Project it is created under.

    Macros can be edited only by their owners.

    only

    When a Project's status is **Macro List Frozen**, ID users cannot add additional Macros and can edit only existing Macros. However, Project Administrators can add additional macros.

12. Click the Macro that you created. **Design View** on the Macro Creation view and select **Devices** to associate with this macro.

13. Click **Design View** on the Macro Creation view and select **Devices** to associate with this macro.


-   **[Associating a Test Assignment to a Testsite Macro](../id_docs/associating_a_test_assignment_to_a_macro.md)**  
**Macro Owners** create **Test Assignments** to request specific tests \(test definitions\) to be executed on a given device. When there are Test Assignments available, a Test Engineer can **Apply** these specific test assignments when creating a Test Plan. This procedure helps ensure that the Macro Owner’s testing intent is followed accurately. In summary, macro owners create Test Assignments for Testsite macros that are sent to Intelligent Test where Test Engineers can apply them in the creation of a test plan.
-   **[Selecting Testsite Macros and Validating Readiness](../id_docs/selecting_macros_and_validating_readiness.md)**  
ID users can submit verification checks on macros they own to help ensure that the verification type is available. ID Users can select Dry Run, Dry Run, and Sentry. Density Checks, and Final Design Rule Check \(DRC\) verification checks. **Dry Run** verification validates configuration, inputs, and sets up for a macro. **Dry Run** and **Sentry** verification combine to validate configuration, inputs, and sets up for a macro and does a fast structural check. **Density** verification helps ensure that macros comply with density constraints. **Sentry** verification checks for fast structural checks. **Final DCR** verification helps ensure that macros comply with all required technology and manufacturing rules. There is no enforced order between flows. When Verification checks are complete, ID User can view the results of the checks by using the overflow menu for each macro. Validation is not performed on incorrect or redundant submissions. ID Users can run multiple flows on the same macro and use the same layout field, but multiple flows cannot run simultaneously. The system stores and can display all verification runs on each macro. After a verification flow is submitted, that flow must be complete or canceled before a new flow can be submitted.
